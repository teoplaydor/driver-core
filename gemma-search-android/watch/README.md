# Пульт кистью — приложения для часов

Повернули кисть вправо и обратно — следующий трек, влево — предыдущий. Часы только присылают **сырые показания
акселерометра** по Bluetooth LE, а поворот распознаёт телефон («Смысловой поиск» → Настройки → «Часы: треки поворотом
кисти»). Поэтому подходят любые часы, чьё приложение может быть Bluetooth LE-клиентом и читать акселерометр. На телефоне
нет SDK производителей. Протокол один на всех, а приложение на часах — маленькое: найти телефон, подключиться и слать
числа.

| Часы | Папка | Готовность |
|---|---|---|
| Wear OS 3+ (Galaxy Watch 4+, Pixel Watch, TicWatch…) | `wearos/` | APK собирается здесь (`wearos/build.sh`); проверено в Robolectric вместе с телефоном |
| Xiaomi Watch S5 (HyperOS / Vela) | `vela/` | `.rpk` собирается здесь (`aiot-toolkit` 2.0.5); код страницы проверен на имитации модулей часов |
| Amazfit на Zepp OS 3+ (Balance, Active 2, T-Rex 3, GTR 4…) | `zepp/` | исходник; код страницы проверен на имитации; собирается `zeus build` |
| Garmin (Connect IQ 3.1+) | `garmin/` | исходник, экспериментально; собирается Connect IQ SDK |

Другие Xiaomi (S4, Redmi Watch 5/6, браслеты Band 8–10) сторонним приложениям не дают быть BLE-клиентом. S4 и Redmi
Watch 5/6 вдобавок не дают читать акселерометр. Для них этот путь закрыт (по документации Xiaomi Vela, раздел Bluetooth,
обновление от 12.05.2026).

## Как это работает

1. На телефоне включается «Переключать треки поворотом кисти». Телефон поднимает GATT-сервер с одним сервисом и
   рекламирует его UUID раз в секунду (режим low power).
2. Приложение на часах ищет этот UUID, подключается, подписывается на ответы и говорит HELLO: случайный id часов,
   частоту, единицы и платформу.
3. Пока играет музыка, часы шлют акселерометр пакетами по 3 отсчёта (20 байт); Wear OS — больше, если связь позволяет.
   Когда музыка останавливается, телефон говорит «пауза», и часы выключают датчик. Связь остаётся, а заиграла — «стрим».
4. Телефон распознаёт поворот (`core/WristGesture.java`). Рука на миг замерла, потом поворот вокруг предплечья на 40°
   (настройка: 30/40/55°) и возврат за 1,2 с. Тогда телефон нажимает «следующий»/«предыдущий», как кнопка гарнитуры, и
   отвечает часам байтом — часы вибрируют.
5. Слушаются только первые часы, сказавшие HELLO («Забыть часы» — чтобы сменить).

Единицы и оси часов телефону не нужны. Величина g меряется, когда рука неподвижна. Направление по умолчанию задаётся
для левой или правой руки, а если часы путают право и лево, «Направление» запоминает один поворот вправо.

Если часы пишут «слушаю повороты кисти», а треки не переключаются: на телефоне в строке «Часы» идёт живой индикатор —
«vela · 25 Гц · наклон NN°». Поверните кисть и посмотрите на число: если оно доходит до ~50–70°, движение телефон
видит, и дело в осях — нажмите «Направление» и поверните кисть вправо один раз (часы у каждого производителя
нумеруют оси по-своему, поэтому направление задаётся одним движением). Если число почти не растёт — данные до телефона
не доходят или единицы странные, пришлите, что показывает строка.

## Протокол

Сервис `a7b7e001-9ca3-4574-a1f0-3c9840e24d01`:

- `a7b7e002-…` — запись (с ответом или без) пакетов часов;
- `a7b7e003-…` — уведомления телефона (дескриптор 0x2902).

Пакеты (little-endian):

```
HELLO  [0]=0x00 [1]=1 (версия) [2..5]=id часов (u32) [6..7]=отсчётов в секунду (u16) [8..9]=единиц на g (u16, 0 — неизвестно) [10..]=платформа, ASCII ≤ 10
ACCEL  [0]=0x10|n (n = 1..15) [1]=номер пакета (u8, +1) затем n × (x, y, z) int16
```

Ответ телефона — один байт: 1 «следующий», 2 «предыдущий», 3 «направление выучено», 0 «поворот, но музыка не играет»,
4 «пауза», 5 «стрим». JS-модуль протокола для Vela и Zepp OS — `vela/src/common/proto.js`, копия лежит в
`zepp/common/proto.js`, и тесты сверяют, что копии одинаковые.

## Сборка и установка

**Wear OS:** `watch/wearos/build.sh` (после `./build.sh` в корне) → `build/watch/WristRemote-wearos.apk`. На часы APK
ставится через ADB по Wi-Fi: «Для разработчиков» → «Отладка по Wi-Fi» → `adb connect IP:порт` →
`adb install WristRemote-wearos.apk`. Запустите «Пульт кистью» и нажмите «Включить». Служба работает и с погасшим
экраном; процессор держится включённым только пока идёт стрим.

**Xiaomi Watch S5:** `cd watch/vela && npm install && npx aiot build` → `dist/*.rpk` (отладочная подпись `aiot-toolkit`).
Сборщик 2.0.5 предупреждает «unknown feature system.bluetooth.ble» — модуль новее его списка, на S5 он есть. На часы пакет
ставится инструментами разработчика Xiaomi (AIoT-IDE); как это делается на вашей прошивке, здесь не проверено. Vela не
пускает датчик и Bluetooth в фон, поэтому страница держит экран включённым, пока работает («Стоп» — отпускает).
Параметры поиска прошивки принимают по-разному: документированные на Watch S5 отклонялись с кодом 202 («неверные
аргументы»; в описании интерфейса Vela у фильтра и опций больше полей, чем в документации). Поэтому приложение
пробует несколько вариантов и запоминает тот, что сработал. Если 12 секунд ничего не видно, оно берёт следующий. Пока
идёт поиск, на экране видно, сколько устройств рядом: если их много, а телефона нет, значит телефон не объявляет себя
(проверьте «Часы» в SemSearch).

**Amazfit (Zepp OS 3+):** `npm i -g @zeppos/zeus-cli`, затем `cd watch/zepp && zeus build` (или `zeus preview` — на часы
через приложение Zepp в режиме разработчика). Тоже работает при открытой странице: экран не гаснет от опускания руки.

**Garmin:** Connect IQ SDK, `monkeyc -f watch/garmin/monkey.jungle -d <ваши часы> -o wrist.prg -y developer_key.der`,
затем скопировать `.prg` в `GARMIN/APPS` или запустить через симулятор/Express. Добавьте модель часов в `manifest.xml`.
Это экспериментальная часть: у Garmin известна ошибка CIQQA-4640 — часы иногда не видят UUID сервиса в рекламе
Android-телефона. Тогда приложение телефон не найдёт. Отсчёты Connect IQ отдаёт раз в секунду, поэтому поворот
срабатывает с задержкой до секунды.

Включение ответов телефона (вибрация, пауза/стрим) необязательно: если оно не проходит за 4 секунды, часы всё равно
начинают слать акселерометр и переключать треки — строка тогда «слушаю повороты кисти (без отклика)». Это запасной
режим: нет вибро-подтверждения и нет паузы датчика при остановке музыки (часы шлют данные постоянно, пока открыты), но
сам пульт работает.

На экране часов при подключении видны отдельные шаги, чтобы понять, где встало: «подключаюсь…» (идёт соединение),
«подключено, узнаю сервисы…» (discovery), «включаю ответы…». Если шаг не отвечает ~8 секунд или соединение не встаёт
за 15, часы отпускают и пробуют снова; после трёх неудач подряд — останавливаются и подсказывают закрыть Mi Fitness.
На телефоне в строке «Часы» видно встречное: «часы подключаются…», когда соединение дошло до телефона.

## Что не проверено

- Ни одни настоящие часы. Сторону телефона и Wear OS проверяет Robolectric, Vela и Zepp — Node на имитации системных
  модулей (по их документации), Garmin — только чтение кода.
- Второе BLE-соединение с телефоном, к которому часы уже привязаны своей программой (Mi Fitness, Zepp, Garmin
  Connect). У Wear OS связь с телефоном обычно идёт по классическому Bluetooth, и отдельное BLE-соединение должно
  получиться. У часов, связанных с телефоном по BLE, это нужно проверять на месте.
- Единицы акселерометра у Vela в документации не названы (скорее всего м/с²). Приложение определяет их само, а телефону
  они не важны.
