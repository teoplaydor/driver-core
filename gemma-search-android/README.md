# Смысловой поиск — прототип на EmbeddingGemma 2

Android-приложение, которое ищет **фото, видео и заметки по смыслу** прямо на телефоне.
Модель — [EmbeddingGemma 2](https://huggingface.co/onnx-community/embeddinggemma-2-ONNX)
(Google DeepMind, 740M, Apache 2.0) в формате ONNX, движок — ONNX Runtime на CPU.
После загрузки модели всё работает офлайн, файлы никуда не отправляются.

## Что умеет

- **Поиск по галерее текстом**: «кот на диване», «закат на море», «скриншот с кодом».
  Текст и изображения лежат в одном векторном пространстве (768 чисел), поэтому запрос
  словами находит картинку на любом языке.
- **Поиск по видео**: из каждого ролика берутся 4 кадра, и они кодируются как одно видео.
- **Поиск по фото**: кнопка «По фото» или «Поделиться → Найти похожее» из галереи.
- **Похожие**: долгое нажатие на результат находит похожие фото, видео и заметки.
- **Заметки**: смысловой поиск по заметкам (запрос «как зайти в интернет дома» находит
  «пароль от Wi-Fi»). Кнопка «Добавить примеры» добавляет демо-набор.
- **Matryoshka**: длину вектора можно уменьшить до 512, 256 или 128 и сравнить качество.
- **Детализация фото**: 70, 140 или 280 визуальных токенов на снимок (быстрее или точнее).

## Установка

1. Скачайте `SemSearch.apk` (arm64, Android 8.0 и новее) и разрешите установку из
   неизвестных источников.
2. Вкладка **«Модель»** → «Проверить» (покажет размер) → «Скачать». Лучше по Wi-Fi.
   Загрузка докачивается после обрыва. Если репозиторий окажется закрытым, укажите
   токен Hugging Face.
3. Вкладка **«Индекс»** → «Начать индексацию» (попросит доступ к фото и видео).
4. Вкладка **«Поиск»** — пишите запрос.

Модель занимает несколько сотен МБ (точный размер покажет «Проверить»), в работе нужно около 1–1,5 ГБ RAM. Индексация идёт,
пока приложение открыто (экран не гаснет). Уже обработанные файлы при повторном
запуске пропускаются.

## Как устроено

```
запрос / фото / кадры видео
   │  HfTokenizer (tokenizer.json, BPE + byte fallback)   ImagePreprocessor (Gemma 4: патчи 16×16)
   ▼                                                       ▼
onnx/model_q4.onnx  ◄── image_features / video_features ── onnx/vision_encoder_q4.onnx
   │  sentence_embedding (768, L2-норма)
   ▼
IndexStore: SQLite + векторы в памяти, косинус по префиксу (Matryoshka)
```

- `src/.../core/`: платформенно-независимая часть (запускается и на обычной JVM):
  токенизатор, препроцессинг, ONNX-пайплайн, загрузка с Hugging Face.
- `src/.../app/`: Android (Activity без AndroidX, MediaStore, SQLite).
- Входы и выходы модели повторяют `EmbeddingGemma2Model` и `EmbeddingGemma2Processor`
  из transformers.js 4.3.1. Промпты взяты из карточки модели: запрос
  `task: search result | query: …`, документ `title: none | text: …`, медиа передаются
  без префикса.

## Что проверено (`test/run_tests.sh`)

| Проверка | Результат |
|---|---|
| Токенизатор против Rust `tokenizers` на реальном словаре Gemma 3 (262k), 6414 строк + 3 варианта конфигурации | 0 расхождений |
| Пайплайн против transformers.js на фиктивной модели с теми же ONNX-входами: текст, 3 формата фото, видео | расхождение ≤ 1e-7 |
| Те же тесты с ORT-классами из APK | совпадает |
| Загрузка: выбор q4, куски `onnx_data`, докачка после обрыва (побайтово), отмена, закрытый репозиторий | ок |
| Приложение на Robolectric (Android 8.1): все вкладки, сценарии без модели, индекс, «похожие», сетка результатов | ок |

**Не проверено**: запуск на реальном телефоне и с настоящими весами (из среды сборки
Hugging Face недоступен). Скорость индексации и качество выдачи надо смотреть на устройстве.

## Ограничения прототипа

- Аудио (поиск по голосовым) пока не подключено: нужен порт log-mel признаков Gemma 4.
- Генеративной модели (Gemma 4 E2B, 1-битный Bonsai) для ответов «своими словами» пока нет.
  Сейчас это только поиск.
- Индексация не работает в фоне (нет foreground-сервиса).
- APK подписан отладочным ключом.

## Сборка без Android Studio

```bash
sudo apt install android-sdk-build-tools android-sdk-platform-23 dalvik-exchange zipalign apksigner openjdk-21-jdk
./build.sh          # → build/SemSearch.apk
./test/run_tests.sh # проверки выше (нужны python3, node, maven, JDK 8)
```

ONNX Runtime 1.30 берётся с Maven Central. Нативные библиотеки — из AAR, а Java API
пересобирается из исходников в байткод Java 8 (`tools/patch_ort.py`), чтобы его принял `dx`.
